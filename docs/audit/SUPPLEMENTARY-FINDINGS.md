# Supplementary Findings — Deep Static Review (Phase-1, post-baseline)

> **Companion to [`AUDIT_REPORT.md`](../../AUDIT_REPORT.md).** The audit report is the PRD deliverable:
> the 7 categories, each *harness-measured* and reproducible via a committed `scripts/audit/catN-*.mjs`.
> **This document holds findings that are deliberately *beyond* those 7** — security, data integrity,
> real-time durability, scaling, reproducibility, and ops — surfaced by a full read-through of the
> repository rather than the category harnesses. The audit report's Ranked Findings table carries the
> `S#` rows (so the risk picture stays unified there); the detail lives here.

**Method (read this first — it matters for how to weight these).** The seven category sections in
`AUDIT_REPORT.md` are *harness-measured* baselines. The findings below come from a separate **full
read-through of the repository** (backend security, data integrity, real-time/scaling, frontend, infra) —
they are **diagnoses by code inspection**, not harness output. Each cites `file:line`; where a finding is
independently reproducible by a one-off query/command that is noted. Every item below was **verified
against source** before inclusion (same discipline as the Cat-6/7 instrument validations — claims that
didn't hold were dropped). **No application code was modified** — this remains a Phase-1 diagnosis.
Severity is re-ranked conservatively by us, not inherited from any tool. Treatment plans for these are in
[`REMEDIATION-PLAN.md`](REMEDIATION-PLAN.md) (§ Supplementary fixes).

### Reproducibility & deploy (relates to Cat 4 / build)
- **S1 [High] Migration `033` fails on a *fresh* database.** `schema.sql:100` declares the `document_type` enum with its *final* values (`weekly_plan`, `weekly_retro`, `weekly_review` — no `sprint_plan`/`sprint_retro`), and `migrate.ts:38` runs `schema.sql` **before** the numbered migrations. Migration `033_sprint_to_week_rename.sql:6-8` then does `ALTER TYPE ... RENAME VALUE 'sprint_plan' TO 'weekly_plan'` on a value that never exists → Postgres raises a *"not an existing enum value"* error, which `migrate.ts:106` does **not** swallow (it only catches `"already exists"`) → `process.exit(1)`. A truly clean clone + `pnpm dev` cannot provision the DB. (We never hit it because the audit restores into an already-migrated DB via the snapshot — which is *why* a fresh-provision path needs explicit testing.) *Reproduce:* drop the DB and run `node dist/db/migrate.js`. **Ironic against the reproducibility theme and worth fixing first in any onboarding pass.**

### Data integrity (relates to Cat 4 / Cat 6)
- **S2 [High] Soft-delete leaks in read paths.** The shared `VISIBILITY_FILTER_SQL` (`middleware/visibility.ts`) filters *visibility only* — not `deleted_at`/`archived_at` — and several reads rely on it as if it were sufficient: backlinks (`routes/backlinks.ts:39-50`), dashboard "My Issues" (`routes/dashboard.ts:90-113`), and the week issue-count rollups (`routes/weeks.ts` — 93 document reads, 1 soft-delete filter). Result: trashed/archived documents appear as backlinks and in the primary dashboard list, and progress metrics **count deleted issues**. *Reproduce:* trash an assigned issue, reload `/api/dashboard` — it still appears. Systemic fix: fold `deleted_at IS NULL` into a shared access filter (or an `active_documents` view) so it can't be forgotten per-query.
- **S3 [High] Hot JSONB equality filters have no usable index.** Only two `properties` indexes exist (`schema.sql:357-358`): a GIN (supports `@>`/`?`, **not** `->>` text-equality) and one expression index on `(properties->>'user_id') WHERE document_type='person'`. The most-queried fields — `properties->>'sprint_number'` (~59 uses), `'assignee_id'` (~35), `'state'` (~28), `'owner_id'` (~44) — fall back to sequential scans. This is the genuine "missing index" the Cat-4 brief asks about; it's masked at 627 docs (<1.5 ms) and bites at 10×. *Fix:* targeted expression indexes per hot field/type.

### Real-time durability (relates to Cat 6, extends RT1)
- **S4 [High] Every deploy can lose in-flight saves.** The only `SIGTERM`/`SIGINT` handler (`db/client.ts:29-41`) calls `await pool.end()` then `process.exit(0)` — it does **not** flush the debounced `pendingSaves` (`collaboration/index.ts:98,185`), and `index.ts` has no shutdown coordinator. The final persist on last-disconnect (`collaboration/index.ts:764`) is also fire-and-forget. So a rolling restart drops any doc in its 2 s debounce window (and worse, ends the pool *first*, so a flush couldn't write even if attempted). This promotes RT1 from "edge case" to "routine, every deploy." *Fix:* a shutdown coordinator that force-flushes `pendingSaves` before ending the pool.
- **S5 [Medium] Client-side failures masquerade as success.** `ApprovalButton.tsx:101-103` (`catch { console.error }` only) lets a failed plan/retro approval revert silently with no toast — a reviewer believes they approved when they didn't. `useAutoSave.ts:39-49` swallows permanent title-save failure after retries with only a `console.error`. These bypass the app's own `MutationCache.onError → toast` pipeline. This is precisely the brief's "real user-facing data-loss/confusion" class (Cat 6).

### Scaling & performance (relates to Cat 3 / Cat 2)
- **S6 [Medium] WebSocket layer won't scale and pins memory.** Broadcast scans the entire global `conns` Map on every keystroke of every room — O(all-connections), not O(room) (`collaboration/index.ts:271`); there is **no `bufferedAmount` backpressure** before `ws.send` with a 10 MB `maxPayload` (`:271,604`); and there is **no heartbeat/ping**, so half-open sockets never fire `close`, pinning `Y.Doc`s in memory and inflating the broadcast cost indefinitely. All in-process state (no shared store) means horizontal scaling requires sticky sessions today. (Corroborates the orientation's RT2 10× hypothesis with concrete `file:line`.)
- **S7 [Medium] Avoidable client load + render cost.** No route-level code-splitting — `main.tsx` eagerly imports all 23 pages including the editor (the mechanism behind the Cat-2 single-chunk finding; 0 `React.lazy`). `QualityAssistant` polls `GET /api/documents/:id` every 10 s regardless of activity (`sidebars/QualityAssistant.tsx:213,341`). No list virtualization anywhere (0 uses of `react-window`/`useVirtualizer`) — large workspaces jank on the issues list / org chart.

### Type contract & tooling (relates to Cat 1 / Cat 5)
- **S8 [Medium] `deleted_at` absent from the shared `Document` type.** `shared/src/types/document.ts:249` has `archived_at` but no `deleted_at`, despite the column existing (`schema.sql:136`) and being central to trash/retention — typed consumers can't reason about trashed state (compounds S2).
- **S9 [Medium] The `lint` script is a no-op.** `package.json:25` runs `pnpm -r run lint`, but **no package defines a `lint` script and no ESLint is installed anywhere** — running `pnpm lint` silently passes. This is worse than "no linter": it presents the *appearance* of static-analysis coverage. (Sharpens the Cat-1 H5 "no linter" finding.)
- **S10 [Medium] E2E flake surface.** **628 `waitForTimeout` hard-waits across 51 specs**, plus `networkidle` waits in a Yjs app (the WS connection never idles), plus known-broken tests marked with `// FIXME:` comments instead of `test.fixme()` (so they *run and fail/flake* rather than being quarantined). `playwright.config.ts:60` sets `retries:1` even locally "for flaky WebSocket/timing tests" — an acknowledgment that flakiness is unresolved. (Cat 5.)
- **S11 [Low] Dead dependency confirmed.** `web/package.json:26` `@tanstack/query-sync-storage-persister` has **0 imports** in `web/src` (the app uses a custom IndexedDB persister) — upgrades the earlier Cat-2 "candidate" to confirmed-removable.

### Cross-cutting — Security & Ops (beyond the 7 rubric categories)
*The brief's 7 categories don't include security or infrastructure; these are surfaced because a senior review found them, and forcing them into a category would misframe them.*
- **S12 [High] Persisted query cache is not identity-scoped → cross-user data exposure on a shared browser.** The TanStack Query cache persists to IndexedDB with `gcTime` 24 h (`lib/queryClient.ts:140`) and `persistOptions={{ persister }}` with **no `buster` keyed to user/workspace** (`main.tsx:255`); `logout()` never calls `queryClient.clear()`/`removeClient()`. A second user on the same machine briefly sees the prior user's document/issue list data (stale-while-revalidate) before the server responds. *Fix:* add a `buster` from `userId+workspaceId` and clear the client on logout/workspace-switch.
- **S13 [Medium] No CI pipeline.** `.github/` is absent — there is **no automated type-check / test / lint gate** between a developer's machine and production; deploys are local shell scripts that ship `dist/` straight to Elastic Beanstalk. (Confirms the orientation's "zero CI".)
- **S14 [Medium] Production Docker is non-hermetic and unhardened.** `Dockerfile` copies prebuilt `dist/` rather than building in-image (artifact has no verifiable provenance), runs as **root** (no `USER`), has **no `HEALTHCHECK`**, pins **pnpm 9.15.4 while the repo declares 10.27.0** (lockfile-resolution drift), and runs **`pnpm config set strict-ssl false`** at build (`Dockerfile:11` — disables TLS verification for package downloads, a supply-chain smell). The dev Dockerfiles build hermetically, so the *production* one is the outlier.
- **S15 [Medium] Repository hygiene.** Four prebuilt **deploy bundles are committed** (`deploy-api-ship-api-2026*.zip`) plus a committed `terraform/environments/shadow/tfplan`; the `.gitignore` globs that were meant to exclude them don't match the actual filenames. **Credential scan: no live secrets, `.env`, or keys in the bundles or git history** (only the dev `admin123` seed value) — so this is hygiene/bloat, not a leak. *Fix:* `git rm` the artifacts and tighten the ignore globs.
- **Positives worth crediting (the review was not all negative):** multi-tenant **workspace isolation is consistently enforced** (no IDOR found); **SQL is parameterized throughout** (no injection); **no mass-assignment**; **auth hardening is strong** (session-fixation prevention, strict cookies, dual timeouts) and the CAIA OAuth flow is textbook (PKCE/state/nonce/redirect-guard); the **Terraform/AWS layer is genuinely solid** (encrypted private Aurora, locked-down S3, SSM SecureStrings, comprehensive WAF, least-privilege IAM); **no secrets in git history**; and frontend **optimistic-update rollback** + Yjs effect cleanup are done correctly.
